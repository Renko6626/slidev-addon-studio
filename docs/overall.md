# 项目定位与整体约束

Slidev Studio 服务于一个人与 coding agent 协同创作 PPT：人在可视化画布里组织内容、调整排版和试播，agent 在同一份 Slidev 工程里编写组件、效果和交互逻辑。双方可以多轮接手，产物始终保留可继续编辑的源码与素材。

这里的 PPT 指演示文稿。当前工程格式为 Slidev，播放依赖浏览器；Studio 文件页尚未提供 PowerPoint `.pptx` 导入或导出。

本文定义产品定位与已有约束。具体能力见[使用指南](usage.zh-CN.md)、[限制说明](limitations.md)和[当前状态](status.md)；本文不授权新增功能或改变架构。

## 创作方式

一次创作可以从人的草稿、已有演示或 agent 初稿开始。典型过程如下，也可以反复回到任一步：

1. 人说明受众、内容、讲述顺序和想要的效果，和 agent 确定本次修改范围。
2. agent 阅读当前工程，完成内容、初稿排版或代码修改，并保留人需要操作的编辑入口。
3. 人在 Studio 中改字、换素材、移动对象、增删页面和试播。
4. 需要调整效果或逻辑时，agent 基于人已修改的工程继续工作，保留无关的位置、文案和素材。
5. 交付工程源码及素材，并说明播放方式、可编辑范围与未验证项。

人负责表达意图和最终取舍，也可以直接创作整页内容。agent 负责用户交给它的内容与实现工作，需要给出可用的排版。双方的分工随任务变化，不能把人的角色固定为最后微调。

目前 coding agent 在外部工具中读取和修改项目文件。Studio 提供工程目录提示、随包技能与接口文档；内置聊天、模型调用、agent 调度和自动执行不属于已有能力。

## 同一份工程

Markdown、Vue 组件、配置和本地素材组成普通 Slidev 工程。可视化编辑和代码编辑都修改这些文件，不另存一份只有编辑器能理解的演示正文。

- 页面结构与配置保存在 Markdown；普通文本、图片和形状沿用现有 HTML、`v-drag` 与 Studio 标记。
- 需要复用或包含复杂效果的内容放在 Vue 组件中；素材放在工程的 `public/` 中。
- 文字、颜色、图片、题目规则等作者配置保存在文稿或 props；作答和游戏进度等运行状态使用现有 runtime/Pinia。
- 工程可以交给 agent、复制到其他目录或继续用 Slidev 命令维护。安装版本和锁文件决定可用能力，源码合并不会自动升级已有工程。

人在 Studio 的未应用草稿尚未落盘。交给 agent 前先应用并保存；agent 修改期间暂停编辑同一页，完成后查看刷新结果。当前通过交接顺序避免同时覆盖文件，不承诺 Studio 与 agent 并发修改同一内容的自动合并。

## 可编辑性

能播放和能继续编辑都属于交付要求。每次实现先确定人需要修改的对象与字段，再决定组件边界。

| 人需要做的事 | 现有实现方式 |
| --- | --- |
| 改标题、题干、说明并独立移动 | 独立 Studio 文本框 |
| 移动、缩放或旋转整张卡片 | 一个带 `v-drag` 的组件 |
| 修改卡片内部文字或图片 | props、`<studio>` 字段声明与 `data-studio-field` |
| 分别移动姓名、头像和说明 | 分开的页面对象 |
| 调整特效算法或业务规则 | agent 修改组件或业务代码 |

复杂特效可以使用 canvas、SVG 或其他已确认的技术；常改的文字和图片应留在页面对象或显式字段中。避免把整页内容封装成只能通过代码修改的组件，也不要求把每个内部参数都做成面板控件。具体字段与定位规则见[组件规范](custom-code/components.md)。

agent 再次接手时先读取文件现状，只改本次任务需要的范围。调整逻辑时保留人改过的 `v-drag`、字段值、素材引用和无关样式；重新排版或重写整页应有明确的任务范围。

## 现有模块边界

| 部分 | 职责与边界 |
| --- | --- |
| 演示工程 | 这份演示的内容、素材、自定义组件与业务逻辑 |
| Studio addon | 画布、编辑面板、源码写回与制作工具；作为普通 Slidev addon 使用 |
| 公共 runtime | 编辑/运行上下文、独立预览与内置题目状态；自定义工程仅使用公共入口 |
| Windows 桌面壳 | 本地工程操作、依赖准备、Slidev 进程和手动 Studio 更新 |
| 外部 coding agent | 按授权修改工程，通过随包技能与文档遵守编辑和接口约定 |

addon、桌面壳与演示工程各自维护版本和依赖。桌面壳是本地入口，使用 addon 也可以从普通 Slidev 开发服务进入。编辑界面仅在开发服务提供；播放内容和公共 runtime 保留在静态构建中。

账号、Git 服务、数据库和协作工作台均不是这条创作流程的前置条件。兄弟项目 `slidev-experiment` 的身份、活动仓库、审核和多人同步由其自身文档约束，不作为 Studio 的默认需求，也不因本次定位整理而删除。

## 交互与副作用

缩略图、组件库和辅助视图会挂载组件。`mounted` 不代表正在放映：页面业务操作检查 `context.active`，整场服务观察 `runtime.canRunServices`。预览数据与主运行状态隔离，import 时不联网、计时或提交答案。

内置答题复用 `useQuiz()`；自定义 store 使用当前上下文的 Pinia。配置和试播状态分开，不复制内置题目的答案或计数。当前共享状态仅在当前浏览器内存中，手机答题、多人比分、远程控制和跨设备持久化均需另行确认服务方案。

只有明确配置的服务才启动，创建的连接、监听和定时器随作用域停止。实现细节见[代码约定](custom-code/conventions.md)。

## 范围与改动决策

按个人创作、低频编辑和可人工处理故障的场景决定复杂度。优先完成内容、可编辑性、预览和播放；发生安装、保存或网络错误时，沿用清晰提示、日志、检查文件和人工重试。

下列变更先展示可行方案、主要取舍和推荐理由，获得明确确认后实施：

- 技术栈、重要依赖、数据模型、公共接口、部署方式或重要模块边界的变化。
- 多人在线编辑、云端平台、手机端或后台服务。
- 引入额外算法、状态机、请求队列、恢复流程、数据库字段或跨模块协调的防御性功能。

日常局部修复和沿用现有架构的实现可以直接推进。理论风险和“以后可能需要”不自动成为需求；抽成共用模块也不能代替功能必要性与授权判断。

## 交付和验证

交接应说明可独立拖动的对象、可改文字与替换素材的入口、仍需代码修改的部分，以及试播和重置方式。交付必须区分源码、工程实际安装包和桌面版本。

运行与改动相关的已有检查；新增永久测试只填补具体 bug 或关键行为的覆盖缺口。文案、样式和布局默认不新增测试。浏览器默认最多截图，不自动点击、填写或跑交互流程。构建或模拟测试通过不能替代 Windows、输入法、剪贴板和现场音视频验收。

源码修改、提交推送、npm 发布、桌面打包与已有工程升级是独立动作，按本次授权范围交付。相关检查通过且任务满足后结束验证，报告实际命令、结果及未验证项。
