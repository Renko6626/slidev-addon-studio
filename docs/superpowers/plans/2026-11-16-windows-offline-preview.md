# Windows 标准工程离线试包

用户已选定随软件携带固定版本离线依赖，要求打 Windows 包试用。沿用 Electron 内置 Node、pnpm 10.33.0、Slidev 52.19.0 与现有工程结构。

- [x] 打包时生成标准 manifest/锁文件，以 Windows x64 为目标收集完整 pnpm store，包含原生可选依赖。使用随包 pnpm，不从开发机全局缓存随意拷贝。
- [x] 新标准工程复制锁文件；首次从随包 store 执行 frozen/offline 安装，不执行安装脚本。安装后的工程独立保存依赖。
- [x] 标准工程依赖与随包基线一致、已安装锁一致且 CLI 存在时直接启动。源码或素材编辑不触发安装。自定义工程保持既有流程，不覆盖版本；离线失败报错，不自动联网重试。
- [x] 缓存放在完整解压的应用资源目录，试包要求解压到可写目录。沿用 pnpm 的文件结构，不新增下载器、持久任务状态或恢复机制。
- [x] 复用现有桌面测试，覆盖锁文件随新建工程复制、标准/自定义分流及已准备工程跳过安装。实际离线安装用临时工程和随包 store 验证，核对 Windows 二进制库存。
- [x] 打出独立预览版本 ZIP，记录体积与检查结果。没有 Windows/Wine 时明确实机启动、路径和窗口操作尚待用户试用；不把 Linux 检查当作 Windows 验收。

本轮不发布 npm、不新增云端构建工作流，也不自动升级用户已有项目。

实施证据：桌面相关 7 项测试通过；修改的 CJS 语法与 diff 检查通过。独立缓存收集 715 个依赖，展开约 505 MiB。实际 createProject、runtime.install 与 dependencyPreparation 在新临时工程运行，注册库设为不可访问地址，下载数 0、安装约 4.2 秒，随后 needsInstall=false。Windows 原生依赖文件头已核对；无 Windows/Wine，不声称 Windows 实机运行通过。

单轮只读审阅未发现核心阻塞；恢复了启用 Studio 在锁文件转换确认之后执行的原顺序，避免取消后改写工程。没有增加重试或恢复机制。离线 ZIP 约 280 MiB，最终文件与校验值保存在工作区 release 目录。
