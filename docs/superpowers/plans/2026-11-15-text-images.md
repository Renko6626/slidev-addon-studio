# 文本框和图片编辑实施计划

> 历史阶段记录。当前功能、版本状态和已知限制见 [阶段状态](../../status.md)。后续阶段可能已完成文中的暂缓项。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans when implementation is authorized. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 从空白幻灯片创建文本框和图片，完成输入、常用格式、位置尺寸调整和图片替换，全程无需手写 Markdown。

**Architecture:** 建议沿用现有 Vue 界面、原位文字编辑、源码定位、`v-drag`、Markdown 写回及素材 API。新文本框使用原生 HTML 容器，新图片使用原生 `img`；少量可读 `data-studio-*` 属性区分新要素，内容仍保存在当前 Markdown 文件，图片文件仍在 `public/`。

**Tech Stack:** 现有 Vue 3、TypeScript、VueUse、Vue I18n、Slidev、Vitest；不新增依赖。

**Spec:** 本文“产品范围与交互”定义本阶段建议范围；已有编辑器边界参见 `../specs/2026-11-14-studio-editor-design.md`。

**Status:** 用户已确认本计划并授权直接实施。沿用当前功能分支，完成后交付一个聚焦文本与图片的提交。

## Global Constraints

- 不做 SVG 基础形状、图形库、多选、分组、连接线或通用图层引擎。
- 不接入 Git、工作台、账号、数据库、桌面框架或新编辑器依赖。
- 沿用现有源码定位及保存路径；已有普通段落和组件保持原行为，不批量转换文稿。
- 新增用户文案同步中英文；字体单位明确为幻灯片画布的 CSS px，不伪装成 PowerPoint 的 pt。
- 新要素在关闭 Studio、放映和静态构建中仍由原生 HTML / Slidev 渲染，不依赖编辑器样式才能显示。
- 防御处理限于明确错误提示与停止错误写入；不引入请求队列、恢复流程、持久对象 ID 或自动素材清理。
- 实施时集中运行相关已有检查。永久测试覆盖关键新行为；截图检查不执行自动点击、输入、拖动流程。

## 产品范围与交互

### 文本框

1. “插入 → 文本框”在当前画布中央创建新对象，建议宽度为画布宽度的 40%，初始高度自动，字号 28px，行高 1.3，左对齐、无边框背景、字体和颜色跟随主题。
2. 创建后直接选中新对象并进入文字编辑；初始“输入文字”全选，输入即可替换。取消本次输入保留已创建的文本框，撤销创建可移除它；不另建临时草稿生命周期。
3. 输入支持中文、多行、换行与纯文本粘贴，复用现有局部加粗、斜体、下划线等工具。已有应用/取消方式保留，输入期间不逐键写文件。
4. 单击选中整个文本框，双击编辑文字；点击内部段落或格式标签也归属于整个框。复制、移动、旋转、删除作用于整框；打字时 Delete 作用于文字。
5. 选中态提供整框属性：字体类别（主题默认、无衬线、衬线、等宽）、字号（8–200px）、字色、左/中/右对齐、行距（1、1.3、1.5、2）。字体类别直接使用浏览器通用族，不扫描本机字体、不上传字体文件。
6. 整框字号/字色/行距在右侧属性设置，顶部开始区放常用字号、字色和对齐；两处复用同一写回函数。文字输入期间先应用当前编辑再修改整框属性，避免两个入口同时覆盖同一段源码。
7. 拖动文本框宽度触发换行并重新计算高度，首版文本框只开放左右宽度手柄与已有旋转操作；不把文本框拉高后自动放大文字。高度显示为自动，避免与本轮自动增长语义冲突。

普通 Markdown 段落保留在现有基础块目录中，新文本框不替换原“标题/正文/列表”的排版语义。

### 图片

1. “插入 → 图片”提供“从文件”和“素材库”。文件入口单选一张图片，完成上传与尺寸读取后立即插入；素材库选择现有图片时直接插入，不要求按 Shift 才获得自由定位。
2. 复用已支持的图片类型；SVG 作为完整图片使用。此入口不接收视频，原有素材库的视频功能保持原状。
3. 初始图片居中，保持自然长宽比，建议外框最大为画布宽度的 60%、高度的 65%，默认不放大超过自然像素尺寸。完成后关闭选择面板、自动选中新图并展示图片属性。
4. 复用移动、旋转、坐标和尺寸输入。图片默认锁定当前外框的比例；角点拖动与数值改宽/高均联动另一维。解除锁定后沿用现有自由缩放；其他元素原有 Shift 行为不改变。锁比时吸附不得再次拉坏比例，必要时保留移动吸附、暂不进行尺寸吸附。
5. 外框与图片显示分别控制：“完整显示”为默认，等比显示全部内容，比例不同时允许留白；“填满外框”居中填满，超出部分不可见。使用 `object-fit` 和居中位置实现，不产生裁剪后的新文件。
6. “更换图片”支持从文件或素材库选择；只更新图片来源及必要的说明，保留外框位置、大小、旋转和显示模式。保留原替代文字供用户修改，不自动用新文件名覆盖已有描述。
7. 图片属性提供替代文字和上述显示模式。删除对象只删除文稿引用；撤销更换恢复原引用，不删除已经上传的素材文件。
8. 取消选图不改变文稿。上传或解码失败显示现有错误提示，不能插入坏路径。若上传完成前用户已离开原页，保留已上传素材并提示重新选取，不把图片写到新页，也不自动重试。

### 共同体验与界面

```text
插入：  文本框   图片 ▾   标题   列表   代码   组件
                  从文件
                  素材库

选择文本框 → 顶部常用文字设置；右侧整框格式与位置
选择图片   → 右侧更换图片、显示模式、替代文字与位置尺寸
```

创建统一采用“落在画布上 → 准确选中新对象 → 打开对应属性”。新建文字和图片都追加为独立源码块，不插到一个已有文本框内部。使用新块的源码范围完成选择，不继续仅靠页面最后一个匹配标签猜测。原有动画、组件和旧文稿编辑不受这两个要素的专用控件影响。

## 源码表达建议与取舍

推荐直接输出带 `v-drag` 的 `div` 和 `img`，以 `data-studio-element="text"` / `"image"` 标记新对象，图片比例开关用一个简单属性保存。文字格式为根容器上的 CSS 属性，文字内容为受当前编辑器支持的 HTML 子节点；图片 URL、替代文字、显示模式直接对应 `src`、`alt`、`object-fit`。

这沿用现有存储路线，具体标记及整框 HTML 编辑已随计划确认。另一条路线是新增 `StudioText/StudioImage` 组件，容易统一 props，但会让这些基础内容增加渲染组件依赖；本阶段没有采用它的必要。也不引入 JSON 场景模型。

只对明确标记的新要素启用完整专用编辑能力。现有未标记图片和普通文字保持原有编辑，不自动转换，暂不承诺任意复杂旧 HTML 都能使用全部新控件。

## Review Focus

- 点击文本框内部段落仍选择整框，编辑多行文字后位置与格式不丢失。
- 插入到已有多个相同标签的页面时，选中的确是新增对象；不建立持久对象 ID。
- 修改一项样式或更换图片时，其他属性、位置与不相关源码不被重写。
- 图片替换为不同长宽比时保持外框；锁比修改尺寸与画布缩放互不混淆。
- 普通路径、Vite 子路径、关闭 Studio 和静态构建中的图片与文字显示一致。

## 用户试用验收清单

1. 从空白页插入文本框，直接输入两行中文，应用后改变字号、颜色、对齐和宽度；重新打开页面内容与外观保留。
