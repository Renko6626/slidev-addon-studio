# Studio internationalization implementation plan

**Goal:** Add English and Simplified Chinese using the user-selected Vue I18n dependency.

**Architecture:** A Studio-owned Composer is shared by UI and setup functions. Message catalogs are typed; locale choice is reactive and persisted. Existing editing and file-writing paths remain unchanged.

**Tech stack:** Existing Vue 3 / TypeScript / Vitest, plus Vue I18n 11.

**Spec:** `docs/superpowers/specs/2026-11-08-studio-i18n-design.md`.

**Constraints:** Work in the existing clean `codex/studio-editor` checkout. Do not change the host app's i18n, user content, asset routing or editing behavior. Follow user test-scope rules: no permanent tests for individual strings; no browser interaction automation. Do not publish or push.

## Tasks

- [x] Add the dependency and typed `client/i18n/{index,en,zh-CN}.ts` catalogs. Export the shared Composer, locale setting, translation function and translatable history action labels. Add a small test of actual locale switching and interpolation.
- [x] Translate toolbar, dock, panels, inline editor, field parts, selection labels, context menu and built-in catalog labels. Use computed values for translated arrays. Add an accessible language select using existing styles. Keep identifiers and authored snippets unchanged.
- [x] Update README with locale behavior and translation contribution guidance. Run existing tests/typecheck, Vue template compilation and playground build; review the final diff and record remaining limitations.

## Review focus

Language changes must refresh computed option labels and undo tooltips. HTML-looking text and Vue I18n special characters must be represented safely. Dynamic prop/component names remain literal. No global host translation registration. Published decks must remain buildable. Server diagnostic messages are outside this client translation pass.
