# Studio 拖动与点击切换

状态：用户已确认并授权实施。本阶段先改善拖动和对象切换，之后另行设计文字区的系统调整。

## 目标与范围

让用户无需先点一次选中再拖动；结束文字输入后，点击另一对象即可转移选区。保留 Vue、真实 Slidev 画布、现有源码映射与 Markdown 写回。

本阶段不调整文字格式工具、字体与字号能力、富文本表达、多选、分组、图层、视图缩放或页面撤销。

## 方案与取舍

采用上一轮推荐、用户认可的现有架构内局部改进：接通选择与现有拖动入口，并明确文字提交与对象切换的顺序。它直接解决当前操作中断，影响范围可控。

替代方案是统一重建对象和交互模型，长期更便于承载复杂对象操作，但会扩大存储、组件与源码往返的改造范围；本阶段不采用。

## 交互约定

1. 未选中的可移动对象：按下即选中，保持按住并移动即可拖动；没有超过阈值时只选择，不写入位置。
2. 已选对象：继续使用现有拖动、缩放与旋转入口。初始保留自由对象 4 屏幕像素、文档流对象 12 屏幕像素的移动阈值，避免轻微手抖改变文档结构。
3. 双击文字仍进入原位编辑。双击识别应针对同一对象及相应手势，不把快速切换对象或连续拖动误判成文字双击。
4. 编辑 A 的文字时点击画布上的 B：提交 A 的内容，并用同一次点击完成选择 B；提交完成后的旧选区恢复不能把选择拉回 A。B 不因这次单击自动进入文字输入。
5. 编辑文字时点击幻灯片空白：提交文字并取消对象选择；普通选中态点击幻灯片空白也取消选择。
6. 点击正在编辑的文字内部继续移动光标或选择文字；点击浮动文字工具保留编辑态。属性栏、工具栏和素材库沿用各自的操作语义。
7. 拖动预览继续实时绘制，松开后一次写回。文字提交尚未完成时遵守现有写入保护，不为连续拖动加入请求排队或手势回放。

## 已查明的原因与修改位置

- `useSelection.ts` 的首次按下只更新 selection，拖动只由随后出现的 `SelectionLayer.vue` 覆盖层启动。通过 `StudioRoot.vue` 接到现有 gizmo 即可复用移动实现。
- 选择监听先注册，遇到 editing 直接返回；`InlineEditor.vue` 后注册的外部点击监听才执行 apply。需要明确一次点击中的提交和选择交接，不能仅调整监听顺序。
- `StudioRoot.vue` 的 commit 在异步写入后恢复提交开始时的选区。切换时应避免旧操作覆盖用户的新选择，并沿用现有源码重新定位能力处理重渲染。
- `useTransformGizmo.ts` 的双击保护目前仅比较时间与坐标；接通首次拖动时需同时检查对象及手势，保留文字双击的保护目的。

具体局部函数与回调由实施者决定，不新增依赖、持久对象 ID、后端接口、全局交互状态机或恢复机制。

## 验证与交付

针对首次按下拖动、轻点不写入、双击保护及文字提交后选择不回跳补充最少必要的行为回归检查，优先复用现有 Vitest 与 composable 测试方式。不以源码字符串断言或大型 DOM mock 替代真实逻辑验证；若现有环境无法有效覆盖某项，明确留给手动试用。

完整改动集中运行 `pnpm test`、`pnpm typecheck` 及必要的 Vue 编译检查。浏览器最多截图，不自动点击、输入或拖动。用户试用重点是首次拖动、连续拖动、双击中文编辑、输入后点击其他对象以及点击空白；自动检查通过不等同于手感验收。
