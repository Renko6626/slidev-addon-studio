# 标题与段落共用富文本

用户已澄清：普通标题和段落能改字，缺少的是 Studio 文本框已经具备的自由富文本格式。沿用既有 Tiptap 引擎、命令及保存链路补齐原生文字，不更换技术栈或引入对象数据库。

## 行为

- 普通 ATX Markdown h1–h6、段落及独立 HTML 标题/段落接入当前字体、字号、颜色、粗斜体、下划线、删除线、对齐、行距、列表、缩进和编辑历史。Setext 标题保持原编辑路径。
- 选中文字修改局部；光标设置后续输入格式；只选中块时修改整块。进入这些文字的编辑会显示“开始”，F2 和保存与文本框一致。
- 单个原生块就是一次编辑范围，不自动合并旁边的标题、组件或段落。Enter 产生后续普通段落；显式列表命令允许改变块类型，生成的标准 HTML 列表可继续编辑。
- 不改动时不重写源文件。简单 Markdown 标记仍写回 Markdown；字体/字号/颜色等无法用 Markdown 表达的格式写成标准 h1–h6、p、span 或列表 HTML，保留标题层级和文档流。
- 已有 HTML 根标签的 class、id、style、定位和动画属性保留；样式不被复制成全局主题快照。不新增自由定位，不添加 data-studio-element="text"。
- 改写 HTML 后重新映射选中块，避免 Markdown → HTML 的 kind 变化使选区丢失。保存仍是既有整段源码撤销，编辑会话内复用 Tiptap 历史。
- 只接入能确认无损读取的独立原生文字。嵌套组件内部、frontmatter、模板插值、自定义内文、图片等保持现有路径，不能从渲染 DOM 反推并覆盖其源码。

## 实现

`client/text/source.ts` 在原生块与现有编辑器 HTML 间做小范围读写适配；文本框保留原有读写。`useTextEditor` 统一选区、命令和提交，`InlineEditor` 复用其应用逻辑；功能区只调整可用性和提示。无新依赖、服务接口、队列或恢复机制。

## 验证

复用现有 jsdom 富文本测试，验证 Markdown 标题局部格式、原生块整块格式、HTML 根属性保留、重开读取、无修改不写、受限源码回退及新增段落/列表。集中运行既有测试、TS、Vue SFC 和静态构建；临时 HTTP 工程验证改写后编译。浏览器不自动点击、输入或交互，真实选区与输入法仍由用户试用。
