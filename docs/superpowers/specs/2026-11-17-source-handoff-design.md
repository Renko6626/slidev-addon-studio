# 源码定位、agent 交接与桌面管理

用户已确认上一轮推荐的轻量方案：复杂代码由外部 coding agent 修改，Studio 提供源码查看、定位和上下文交接；保留应用之外的恢复入口。不建设 Vue/TS 编辑器，不将完整 Studio 拆成独立渲染应用。

## 范围及取舍

“查看 → 源码与 agent”打开只读侧栏。复用 Slidev 当前页 info.source 的原始 Markdown、文件路径和范围；复用组件 catalog 的 Vue 路径、项目文件树的 TS 路径。脚本列表只用于定位，不声称自动推断当前页依赖。提供复制当前页、路径及 agent 上下文；上下文包含工程目录、页码/文件位置、选中组件、已有错误及制作约束。正文在 `<textarea readonly>` 中可手工复制，剪贴板失败不阻断查看。

相比完整 IDE，此方案不增加任意文件读写、代码执行、编辑器依赖或转换 API；保留已有局部标签编辑。本轮不自动启动或绑定特定 coding agent。

桌面由宿主安装原生工程管理菜单，Alt 可访问菜单，Ctrl/Cmd+Shift+M 弹出管理命令；不依赖页面 Vue 或 Vite 编译。菜单可打开目录、查看日志、复制工程诊断、重新加载工程和返回主页。后两项先经原生对话框确认可能丢失未应用编辑，随后直接使用磁盘文件；不调用页面保存钩子。保留最近尝试打开的工程位置，启动失败后仍能定位。仅这两项走显式恢复路径，普通保存/关闭行为不变。

诊断复用当前运行日志，不新建错误收集服务。正常页面的 agent 上下文可带最近 Vite 编译错误。组件库预览补齐子组件运行错误捕获，其他预览不受影响；单页错误页及缩略图沿用既有机制。

保证的是编译失败时宿主管理入口可用，不承诺完整可视化编辑器始终可用，也不承诺隔离任意用户脚本阻塞渲染线程。外壳分离为独立项目，后续若需要另行设计。

不发布、不打包、不改变依赖和部署；浏览器仅导航及截图。
