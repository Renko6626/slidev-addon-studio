# Windows 桌面版

Windows x64，分发 ZIP 直接使用 Electron 自带的 Node。用户无需安装 Node、pnpm、Docker 或工作台服务。轻量版随附 Studio，缺少的依赖安装时联网获取。完整版额外随附标准工程的 Windows x64 依赖缓存。两者采用同一安装和更新流程。

Studio 与桌面壳可以独立更新。桌面稳定版为 0.5.2。0.5.4 预发布提供轻量版和完整版，均随附已在 npm 发布的 Studio 0.5.3。[下载桌面 0.5.4](https://github.com/Renko6626/slidev-addon-studio/releases/tag/desktop-v0.5.4)

## 使用

完整解压 ZIP，在解压目录中运行 `Slidev Studio.exe`，不要只复制 exe。

- **新建工程**：选择一个新的空文件夹。应用从随附包和已下载包中选择本机最高正式版本，生成普通 Slidev 工程与依赖清单，安装后进入编辑器。新建不查询云端。
- **准备进度**：主页显示创建工程、安装依赖和启动编辑器的当前阶段。等待时显示滚动进度条、已用时间及最新安装信息。包数量来自 pnpm 实际输出。进度下方可以打开运行日志，联网和排查说明收在“启动帮助”里。
- **打开工程**：选择已有工程文件夹，默认打开 `slides.md`；没有默认入口时再选择 Markdown。依赖版本按工程清单保留。
- **导入工程 ZIP**：首页和新版 Studio 文件页选择 ZIP 及空目标目录，解包后按打开工程的流程选择入口、准备依赖。支持子目录入口，保留原有内容与依赖配置；不导入 PPTX。取消入口选择时已解包文件留在目标目录，可稍后打开。
- **导出演示**：新版 Studio 文件页先保存，再在系统浏览器打开 Slidev 导出页，支持 PDF、PNG 压缩包和图片型 PPTX。采集图片时选择共享当前标签页，导出期间保持工程打开。PPTX 内的文字和对象不能单独编辑。
- **启用 Studio**：仅对尚未启用 Studio 的工程询问是否启用本机可用版本。确认后添加 `vendor/slidev-addon-studio-X.Y.Z.tgz` 并设置 `file:` 依赖及启用配置；保留其他直接依赖和文稿。已有工程继续使用自己的 Studio，旧固定文件名也可继续打开。
- **另存为**：先保存当前编辑，再按工程 ZIP 的规则复制到工程外的空文件夹，然后打开副本。依赖、缓存、Git 历史和本机凭据配置不会复制。
- **关闭工程**：先保存，再停止本地 Slidev，回到欢迎页。窗口关闭也先检查保存；失败时留在编辑器。
- **日志**：欢迎页或编辑器“文件 → 打开运行日志”查看依赖安装和编辑进程日志。发生错误后可修正文件，再重新打开，不自动重试。

窗口原生按钮叠加在 Studio 标题栏，空白区域可以拖动窗口。欢迎页和非全屏预览保留窗口拖动区域。原生菜单默认隐藏，按 Alt 显示；Ctrl+Shift+M 弹出“工程管理”。日常工程操作在编辑器“文件”页；Ctrl+N 新建，Ctrl+O 打开，Ctrl+Shift+S 另存，Ctrl+Shift+I 打开开发者工具；Ctrl+S 保留 Studio 的保存行为。

原生工程管理不依赖项目 Vue/Vite 编译，可打开当前或最近尝试打开的工程目录、查看日志、复制工程诊断，以及重新加载工程或返回主页。重新加载与返回主页先明确确认可能丢失尚未应用的编辑，再直接使用磁盘文件；这两个操作不调用页面保存钩子，也不自动回滚源码。普通关闭、另存和更新仍按原保存检查执行。使用外部 agent 修正编译错误后可重新加载；完整可视化编辑器仍与文稿共用应用。Windows 原生菜单、快捷键、确认对话框及错误工程实际恢复需实机验收。

“文件”页的项目路径可点击打开文件夹；“查看 → 源码”提供当前页源码、相关文件位置和页面信息复制。使用外部工具修改工程的说明见[接入指南](../docs/custom-code/agent-guide.md)。 人和 agent 接续修改同一工程，整体约束见 [overall](../docs/overall.md)。先应用并保存，再交给 agent；期间暂停编辑同一内容，完成后查看刷新结果。

标准工程核对工程选定的 Studio、依赖配置、已安装版本和锁文件；环境一致就直接启动，不要求 Studio 版号等于桌面版号。自定义依赖或尚未准备好的工程执行 pnpm install 并优先复用缓存；匹配完整基线时按下文离线安装。普通打开不查新、不自动升级，锁文件继续约束依赖。已有 npm/Yarn 工程需要安装时，会先询问是否导入锁文件并生成 pnpm 锁，原锁保留。也可以取消，在外部准备依赖后打开。

选择“保留工程现有环境”时，旧版 addon 可能没有新的文件页或保存接口；离开前应用会明确要求自行保存。首版按可信的个人工程使用；Slidev 配置和依赖按普通本地工程执行。没有附带第三方原生模块的 C++/Python 编译工具链。

## 网页播放包

播放电脑安装 Studio 后可打开普通工程直接放映。无需编辑的交付也可选择“文件 → 导出网页播放包”，保存为 Windows x64 ZIP。该入口需要同时使用支持此能力的桌面壳与 Studio addon；旧壳和独立浏览器不显示。

选定位置后，导出先应用并保存文字、备注，再调用工程自己的 Slidev CLI 生产构建。原编辑服务继续运行，工程文稿、依赖、锁文件和既有 `dist` 保留。导出期间请保持文件页打开、暂停修改工程。保存或构建失败时不覆盖已有目标；查看运行日志并修正后重试。

播放包内容为 `start.cmd`、`miniserve.exe`、`web/`、`README.txt` 和 `licenses/miniserve-LICENSE.txt`。完整解压后双击 `start.cmd`，脚本启动本机服务并打开系统浏览器，不需安装 Studio、Node 或 Rust。默认地址为 `http://127.0.0.1:8080/`；关闭服务器窗口停止服务。端口冲突可修改脚本中的 `STUDIO_PLAYBACK_PORT`，浏览器打开过早可刷新。没有端口扫描、自动杀进程、后台服务或开机启动。

网页保留动画、答题和浏览器媒体能力，默认移除演讲备注、不附带 PDF 下载，也不提供源码编辑。外链素材、网络字体、远程业务仍可能联网，导出保留作者配置，不自动抓取或替换。媒体解码、自动播放和全屏依赖浏览器及设备。保留源工程或工程 ZIP，修改后重新导出。网站从根路径提供，不承诺可直接部署到任意子路径。

桌面轻量版和完整版都随附 miniserve 0.35.0 的 Windows x64 程序（约 2.09 MiB），许可为 MIT。固定发布地址与 SHA-256 见 [`playback/miniserve.json`](playback/miniserve.json)。开发/打包准备阶段校验并复用或下载到 `studio-resources/playback/`；二进制不进 Git 和 addon npm 包。导出不下载播放器，资源缺失或校验失败时重新准备或安装桌面程序。miniserve 随桌面壳更新，不随工程内的 Studio 包更新。

## 检查和更新 Studio

欢迎页提供“更新工程内 Studio”，支持该宿主能力的“文件”页提供“检查 Studio 更新”。原生对话框显示本机版本、npm 最新发布版本，以及当前工程版本（如已打开）。仅手动检查联网；取消或没有更高版本时不安装、不降级。

- 没有打开工程：选择“下载更新”，取得经 SHA-512 校验的 tgz，之后新建工程使用这个版本。
- 已打开工程：选择“更新并重启编辑器”，先取得归档，再完成保存，随后停止旧服务、更新当前工程的 Studio 依赖、安装并重开。其他工程不变。
- 查询失败时可继续编辑；保存失败停止更新。安装或重启失败会显示错误和日志，用户可修正后重新打开，不自动回滚或重试。

随附 Studio tgz 和 `studio-package.json` 记录一个明确版本。下载归档保存在 Electron 用户数据目录的 `studio-packages`；工程保留自己的 `vendor` tgz，ZIP 导出会带走它。第三方依赖缓存仍由 pnpm store 管理，工程运行使用自己的 node_modules。不会自建注册库或包数据库。

完整版本的旧缓存不保证覆盖新版新增的依赖。更新时可复用缓存，缺少的依赖仍需联网。该入口更新 Studio，不更新 Electron、窗口或原生文件功能；旧壳需要先换成支持该入口的桌面版本。

## 客户端版本与更新日志

欢迎页“版本与更新”离线显示当前客户端、随附 Studio 版本和本版更新日志。打开工程后可按 Alt 显示原生菜单，从“帮助”进入；这些入口不依赖工程编译成功。

点击“检查客户端更新”才会连接 GitHub。查询只选择 `desktop-vX.Y.Z` 的稳定发布，且必须有对应 Windows x64 轻量 ZIP；npm 版本、草稿和预发布包不会显示为稳定客户端。“查看更新与下载”在系统浏览器打开对应 Release，查看完整说明并选择轻量版或离线完整版。网络失败时保留当前编辑，可稍后重试或手动打开发布页。

下载后完整解压到新的可写目录，运行新版并打开原工程。不要只替换 exe 或混合覆盖旧目录。客户端查新不会下载或安装更新，不会保存、重启或改写工程；工程内的 Studio 仍使用自己的依赖，另按上一节明确更新。

## 开发与打包

开发机需要 Node 22.13+ 和 pnpm。根仓库与 desktop 各自安装依赖：

```bash
pnpm install --frozen-lockfile
pnpm --dir desktop install --frozen-lockfile
pnpm desktop:dev
```

Windows ZIP：

```bash
pnpm release:build
# 可选完整版
pnpm release:build --offline
```

正式产物归档到仓库相邻的 `release/studio/<桌面版本>/`：ZIP 使用桌面版本，`slidev-addon-studio-<Studio版本>.tgz` 使用 Studio 版本，校验表按模式区分。online 表示轻量版，offline 表示完整版。`desktop/out` 是 Forge 中间输出。正式打包从 npm 获取根 package.json 指定、已经发布的精确 Studio tgz；未发布则停止，不改用本地源码。`desktop:dev` 仍从当前源码 pack。必须先编写 `docs/releases/desktop-X.Y.Z.md`；准备阶段将两个版本和日志原文写入随包 `studio-resources/desktop-release.json`，GitHub 发布也使用该 Markdown。Forge 带入模板和 pnpm JS。`desktop/pnpm-workspace.yaml` 将此工具包与根仓库隔离，并仅在桌面包使用 hoisted 布局。未新增根 workspace 成员。

新建工程固定 Slidev CLI 52.19.0、默认主题 0.25.0、Vue 3.5.41、Markdown-it 14.3.0；后者避免当前 Markdown 插件自动解析到 15 后无法启动。首次安装生成工程自己的 `pnpm-lock.yaml`。现有工程不套用这套模板版本。

## Windows 完整版与离线基线

完整解压到可写目录，例如 `D:\StudioOffline`，再运行 exe。新建工程选中的 Studio 与随附基线一致时，复制随包固定锁文件，以 pnpm 10.33.0 从软件资源目录中的 store 安装；不访问注册库、不执行安装脚本。每个工程保留自己的清单、锁文件、`vendor/` 和 `node_modules`。同卷安装直接使用随附 store，由 pnpm 选择依赖文件的导入方式。

标准工程的依赖、锁文件和配置与基线一致，且已有安装锁及关键入口时，重新打开直接启动。改文字、拖动、换素材不触发安装。只为这一明确基线跳过准备；新增依赖、改版本或导入旧工程仍沿用原有准备流程，不承诺离线可用，也不会替换其锁文件来凑成基线。标准工程离线安装失败会停下显示日志，不自动切换联网安装。

工程与 Studio 位于不同卷时，应用在工程目录运行内置 pnpm 的 `store path`。如果返回的 store 在工程所在卷、位于工程外、可写且能与工程共享硬链接，首次安装会从随附清单补齐该卷的依赖包内容、索引和 Studio 归档校验信息。同卷其他工程复用现有缓存，即使它们放在不同的父目录。已有文件和本地构建缓存继续保留。实际路径遵循本机和工程的 pnpm 配置，详见运行日志。轻量版继续直接使用 pnpm 选出的 store。

目标 store 不可用、无法共享文件，或旧完整版没有文件清单时，应用使用随附 store 并在日志记录原因。写入遇到磁盘空间不足等错误会停下并保留已补齐的文件。手动再次打开可继续补齐。复用时会检查基线原生依赖的索引和包文件，缺失时先补齐再安装。若清理缓存后 pnpm 报缺少其他离线依赖，应用清除完成标记，下次打开时再补齐。

工程 ZIP 带走源码、素材、锁文件和此工程选用的 Studio tgz。接收方用本机缓存或匹配的完整版恢复依赖。另存也按该规则准备副本。只需播放时使用上文的网页播放包。

选中随附基线时建议试用：

1. 解压后先断网，再新建一个空目录中的工程，确认状态显示“从随附文件准备离线依赖”，安装日志下载数为 0。
2. 修改文字、保存并关闭工程；重新打开，确认直接启动编辑器。
3. 在另一个卷上的两个不同父目录分别新建工程，检查日志中的实际 store、首次补齐、后续复用和下载数。试一次另存为，确认副本也能离线打开。
4. 如失败，保留“打开运行日志”中的内容反馈；不要只复制 exe，也不要删除随包的 studio-resources。

离线范围是标准工程的编辑与构建依赖。外链图片、网络字体、在线服务和 agent 新增的包不在这个承诺中。

开发机在两个 ext4 卷上以 Windows x64 目标验证标准工程依赖安装。目标卷 store 占 503.98 MiB。首次准备耗时 19.38 秒，同卷另一目录新建工程耗时 3.57 秒，两次 pnpm 下载数均为 0。第二个工程独占 25.43 MiB，约为同机强制复制对照 544.30 MiB 的 4.67%。分别移除 Rolldown 的 Windows 绑定索引和二进制文件后，新建工程都能在离线安装时补回缺项。另在 Linux 原生工程实测另存、ZIP 导入、网页播放包与静态服务，以及更换 store 后安装自定义依赖。Windows 双 NTFS 卷的磁盘占用、耗时和桌面操作仍待实机验收。

构建并归档完整版：在仓库根目录运行 `pnpm release:build --offline`（`pnpm desktop:make:offline` 也可）。准备脚本在临时工程生成锁文件，以 supportedArchitectures 的 win32/x64 配置收集独立 store，并记录随附文件清单和基线标识。不复制开发机全局缓存。随包 pnpm 安装时会写入缓存元数据，因此软件目录必须可写。普通 `make` 生成不含完整依赖缓存的轻量包。选中较新的缓存 Studio 时，不复制旧离线锁文件；后续安装复用 store 并允许下载新增依赖。


## 版本与手动发布

```bash
pnpm release:version studio 0.5.2   # 只修改 Studio 版本
pnpm release:version desktop 0.5.2  # 只修改桌面壳版本
pnpm release:build                 # 默认轻量版，取得已发布的精确 Studio 包
pnpm release:build --offline    # 需要时再制作离线版
pnpm release:publish --dry-run  # 检查本地产物并预览上传，不联网
```

Studio 发布沿用 `docs/releases/X.Y.Z.md`、根 package.json 和 `vX.Y.Z` 标签；显式推送该标签触发现有 npm 工作流，版号校验不读取 desktop。正式桌面包需要等指定 Studio 版本发布完成，再本地构建。桌面发布使用 `desktop-vX.Y.Z` 标签，必须提供非空 `docs/releases/desktop-X.Y.Z.md` 作为说明；缺失时构建、发布和对应 dry-run 都会停止。本地打包不会发布 npm，版本命令不自动提交或打标签。

GitHub Release 另行手动执行，需先安装并登录 GitHub CLI，且远端已存在对应标签：

```bash
pnpm release:publish --prerelease # 上传轻量版，新建 Release 默认预发布
pnpm release:publish --offline  # 可选：给同一 Release 补充离线版
```

上传命令先核对本地 SHA256，再创建预发布或给已有 Release 上传所选模式。轻量版必须先发布，离线版仅补充到已有轻量版的同一 Release；补充上传不改变发布状态。已有同名资产会报错，不覆盖。每次重新分发内容不同的桌面 ZIP 都使用新桌面版本；平日只更新 Studio 时无需打桌面包。`--dry-run` 也可用于打包命令，查看模式和输出位置。

新建 Release 默认使用 `--prerelease --latest=false`，显式 `--prerelease` 表达相同意图。按精确源码提交创建和推送桌面标签，再构建、校验与上传；脚本不代为推标签。Windows 人工试用至少覆盖解压启动、新旧工程、编辑保存重开，以及工程字体和网页播放包。获得反馈后，再明确提升同一 Release 为稳定版，产物和标签保持不变：

```bash
gh release edit desktop-vX.Y.Z --repo Renko6626/slidev-addon-studio --prerelease=false --latest
```

发布状态提升不重新构建、不覆盖 ZIP，也不改变其他版本。客户端会在下次手动检查时识别稳定版。真实打包、上传和提升稳定各按明确授权执行。

历史安装包按需手动清理；打包脚本不自动删除其他版本、截图或其他项目的产物。


## 启动诊断

首次安装后，Slidev 仍需进行本地编译。桌面启动等待上限为 3 分钟，每次 HTTP 就绪探测允许最多 10 秒；启动输出会显示在准备页。子进程报错或退出会立即结束等待并显示原因，不会一直等到超时。

“打开运行日志”保留各次命令、工程目录、完整安装/启动输出和进程退出原因。若仍失败，请附上失败时最后几行日志；页面加载失败会回到准备页，再次打开不会被误认为已成功打开。
